# Sightline v0.4.1 - Save Persistence

This Windows update addresses [issue #1](https://github.com/mscrnt/Sightline/issues/1):
cartridge progress could disappear after closing and reopening the game.

The native writer stored checksum words and one options field in the PC's byte
order, while the reader expected the cartridge's byte order. The next launch
could therefore reject an otherwise intact save folder and reset it. v0.4.1
writes those fields in cartridge order, commits each EEPROM write to disk, and
recognizes the older native checksum format so an intact folder can be converted
on its first load. A folder that an earlier launch already reset cannot be
reconstructed by this update.

The release package uses the same save location as before:
`%LOCALAPPDATA%\sightline\eeprom.bin`. Keep that file when updating; the package
contains no ROM or player save.

The presentation selector now skips modes whose required assets are not
installed, so F5 stays on ORIGINAL with only the base game. The file-select
difficulty and mission labels are centered on their folders in both 4:3 and
16:9; the native label copy now uses a bounded buffer.

## Validation

- The shipped v0.4.0 executable reproduced the bug in an isolated two-launch
  test: after a clean exit, the first folder checksum was invalid and the next
  launch refused the previously unlocked Runway mission.
- The v0.4.1 package executable passed the same two-launch check; all five
  checked folder records remained valid and Runway remained selectable.
- An intact save written by v0.4.0 was reopened by v0.4.1; its Runway unlock
  remained selectable and the folder was rewritten with a valid cartridge
  checksum. A separate forced-close test found the candidate's committed save
  intact before normal process exit.
- The file-select screen was captured from the native build at 4:3 and 16:9;
  the difficulty and mission labels align with the folder centers in both.

The recorded cartridge trace gate was attempted but could not compare: its
Runway baseline requires a direct-boot ROM image absent from this checkout, and
rebuilding that image failed in the local cross-toolchain. The native save
regression test above exercises the changed code path directly.

The intermittent first-frame NVIDIA OpenGL driver fault described in the
[v0.4.0 release](https://github.com/mscrnt/Sightline/releases/tag/v0.4.0)
remains under investigation. This save update does not claim to resolve it.
