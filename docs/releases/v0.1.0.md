## What the checkpoint contains

Everything below is as of `c489657c`; nothing from the QoL branch is in it.

- **A native Windows executable** (`tools/windows/build.ps1`: PE32 / i686,
  MinGW GCC, SDL2 window and audio, OpenGL renderer) that boots the retail
  game data through the cartridge's own front end — the legal and logo
  screens, file select, mission select, difficulty select — and plays the
  **full single-player campaign**, which the project owner played through
  and accepted on the native build (all 20 missions; not a parity claim).
- **Keyboard and mouse** as a native override at the game's input seam
  (W A S D, mouse look, the mouse pointing the game's own menu cursor); the
  **gamepad** as a virtual N64 controller interpreted by the game's selected
  control style. Quitting is closing the window (Alt+F4); there is no
  in-game quit entry at this checkpoint.
- **Original boot-screen artwork** (the four CC0 models under
  `data/asset-overrides/`), built from committed sources by the build.
- **The correctness spine:** the matching build (byte-identical MIPS ROM)
  and the trace harness, with the determinism gate green — all 20 campaign
  levels replay byte-identically across 10 consecutive runs.
- Phase 1 (severing `src/game` from libultra / excising the RCP) open.

Not in this checkpoint (they are the QoL Phase 1 line, `v0.2.0`): semantic
key / mouse / controller bindings and remapping, persisted settings, the
native front-end and watch settings pages, aspect ratios, FOV, resolution and
window modes, controller profiles and presentation, QUIT GAME.

## ROM requirement

Sightline includes no GoldenEye ROM and no game data. A user-supplied
GoldenEye 007 (USA) dump is required: a plain, uncompressed, big-endian
`.z64`, 12582912 bytes, SHA-1 `abe01e4aeb033b6c0836819f549c791b26cfde83`.
`.n64` / `.v64` dumps are byte-swapped and are not detected.

## Binary artifact

**No Windows ZIP is attached to this checkpoint, and the reason is in the
source itself.** At `c489657c`, `src/platform/sl_acmd.c:17` includes the
build-generated header `build/native/sl_resample_tab.h`
(`tools/native/gen_resample_tab.py`), which places 528 bytes read out of the
user's ROM — the audio microcode's 64×4 RESAMPLE polyphase table and its
ENVMIXER ramp, `aspMainData` +0xC0 and +0xB0 — into the executable as
`static const` data (`sl_acmd.c:289`, `:894`). There is no runtime seam at
this revision: the only way to build the checkpoint is with those bytes
compiled in, and a build made that way was measured to carry them verbatim
(`tools/windows/validate-package.ps1 -Rom …` finds the 512-byte table inside
`sightline.exe`). Shipping that binary would distribute ROM-derived data,
which the project does not do; producing one without the table needs a
source change, which by definition is not `v0.1.0`; patching the binary is
not a release. So the checkpoint is a tag, the build is reproducible from it
(toolchain identity and hashes are recorded in private issue #49), and the
first distributable binary is the QoL release, whose source derives the two
tables from the user's ROM at run time.

The matching build's linker map (`build/u/ge007.u.map`), the other non-Git
input `build.ps1` needs, was regenerated for this checkpoint by
`make matching` at `c489657c` (`MATCH!`, ROM SHA-1 `abe01e4a…`); it is
identical, on every line `gen_segments.py` consumes, to the map the
development host had been building with.

## Windows support statement

Windows 10 / 11 x64, 32-bit build, OpenGL. No other platform.
